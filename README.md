# B站评论批量删除 v2.2（全面优化版）

> **当前版本 2.2.44**（面板开着或关着都会记住，换页之后还是上次的状态）。在 v2.1(三谱系合并)基础上做的**性能 / 网络 / 数据 / UX** 全面优化。上游:Smith-106 v2.0 + WorkBuddy v1.2 + SXM v1.1 + naaammme/bilibili-tools 经验。

## 安装 / 使用

同 v2.1:Tampermonkey 新建脚本 → 粘贴全文 → 打开任意 `*.bilibili.com` 页面点右下角 🗑️。三源枚举:AICU 获取 / 官方历史扫描 / 离线 JSON 导入;关键词+来源+类型+时间排序四维筛选;删除前可 💾JSON/CSV 导出备份。

## v2.1 → v2.2 变更清单

### 性能
1. **列表事件委托**:行内 checkbox / 跳转按钮改为容器级单监听(原来每行 2 个闭包,1 万条 = 2 万个监听器)。
2. **增量渲染**:150 条/块的 IntersectionObserver 滑动续载,大列表不再卡死全量渲染(之前 5000+ 条一次性渲染会冻结)。
3. **O(1) 去重**:rpid 用 `Set` 索引(原来 `Array.some` 全量线性扫描,O(n²)——AICU 10k 评论场景约 5000 万次比较)。

### 网络层
4. **统一请求层**:按 host 串行化(杜绝对接口并发轰炸),GET 对网络错误/HTTP 412/429/5xx 做**指数退避自动重试**(带抖动),B站 body `code=-412` 同样识别为风控。
5. 继承 v2.1 修复:删除请求绝对 URL + `@connect`,不手工拼 Cookie(HttpOnly SESSDATA 本就不可读,依赖 TM 自动附带)。

### 数据与安全
6. **处理日志持久化**(localStorage,上限 2000 条):每条删除结果(成功/失败/待确认)落库;后续看到同 rpid 显示 `上次已删除✓ / 上次失败 / 上次待确认` 徽标,重开页面不丢账。
7. **删除前导出备份**:JSON / CSV(UTF-8 BOM,Excel 直开)。
8. **换号防护**:列表枚举 UID ≠ 当前登录 UID 时,删除前弹明确确认(删除接口只作用当前登录账号,防止"以为在删别人的"误解或误删两号混合数据)。
9. **-509 连续限流耗尽**:显式计入"未生效"(修复 v1.2 静默漏计);中途停止的条目按"待确认"入账,不丢数。

### UX
10. **来源/类型/排序过滤器** + 重试按钮(`↻ 重试未成功(N)`,只跑上批失败/待确认项)、🧹清空列表(不影响已删除记录)。
11. **明暗双主题**(CSS 变量切换,持久化)、面板拖拽定位(位置记忆 + 越界复位)、日志滚动上限。

## 接口

```
枚举  GET  api.aicu.cc / apibackup2.aicu.cc:88 /api/v3/search/getreply
枚举  GET  api.bilibili.com /x/web-interface/history/cursor + /x/v2/reply/main(时间序)
删除  POST api.bilibili.com /x/v2/reply/del(oid,type,rpid,csrf;type=11 → csrf 走 query)
回查  GET  api.bilibili.com /x/v2/reply/detail?type&oid&root&rpid（12006=已删，0=仍在；不可用才退回全区/整楼 walk）
定位  GET  api.bilibili.com /x/web-interface/view?aid(bvid 缓存)
```

## 已知限制 / 风险

- 删除不可逆;首次使用建议小批试删。
- 枚举仍依赖 aicu 覆盖动态/专栏评论(官方历史扫描仅视频);处理日志存于 localStorage,清除浏览器数据会丢徽标。
- **删除接口 code=0 不可信**。风控下会「已受理但没删」。v2.2.2 默认用官方单条接口二次确认，仍在则自动降速重试 2 次。
- 回查遗留的不确定(应极少，且只在单条接口不可用时):① 区域顶评超 200 游标页未走完;② 单楼超过 ~2900 条子回复未翻完;③ 区/楼接口临时异常。三者均给出"待确认+↗跳转"。
- 遵守 B站使用条款,仅用于清理**自己**的评论。

## v2.2.0 → v2.2.1 回查引擎升级(真实运行反馈驱动)

**实跑日志暴露的问题**:1210 条枚举后,大批删除出现"前 10 页未找到,请用↗跳转确认"。
根因:旧版回查逐条扫 `x/v2/reply` 前 N 页的**内联预览**,两类评论永远确认不了——
① 顶评按热度序沉底(老评论在 N 页之后);② 深层楼中楼(根楼内联只带最前几条子回复)。

**新方案:每区域一次全量 walk,可判定**:

| 场景 | 旧(v≤2.2.0) | 新(v2.2.1) |
|---|---|---|
| 顶评(root=0) | 前 5~10 页内联,扫不到就"待确认" | `/x/v2/reply/main` 游标**全区走完**(≤200 页),在/不在即结论 |
| 楼中楼(root>0) | 大概率永远"待确认" | 全区 walk 找根楼:**楼没了 → 子评必然已删**(直接确认);楼在 → `/x/v2/reply/reply` **整楼翻页**(49/页,≤60 页)判定 |
| 删除节奏 | 逐条:删一条查一条 | 两阶段:成批删除 → **每区域一次统一回查**(请求量从 每条×10页 降到 每区×全量一遍) |

- 回查结果缓存按批次生效(删除只移除条目,walk 结果不会失效),同区多条删除零重复请求;
- `-404`/`12022` 也纳入回查判定(不再直接当成功——zone walk 说"还在"则记未生效);
- 剩余"待确认"仅三种边缘:区域 >200 游标页、单楼 >~2900 子回复、接口临时异常,均给原因。

## v2.2.1 → v2.2.2 工作链路与交互反馈

真实账号 1211 条全量删除里确认两件事：删除接口 `code=0` 只表示受理（部分番剧大区会假成功）；6 万条级评论区翻页回查不现实。

| 链路 | v2.2.1 | v2.2.2 |
|---|---|---|
| 回查 | 先全区/整楼翻页 | **先** `/x/v2/reply/detail` 单条（顶评 root=自身 rpid）。12006/-404=已删，0=仍在。单条不可用才退回翻页 |
| 假成功 | 记「未生效」，等人点重试 | 回查发现仍在后 **自动降速重试 2 次**（间隔 2.5s），救回的单独计数 |
| 进度 | 删除阶段一条进度条，回查只有状态文字 | 进度条标注 **①删除 / ②回查 / 完成**；状态行实时显示已受理、已确认、未生效、待确认 |
| 日志 | 「已提交，待统一回查」 | 「接口已受理（不等于已删），待官方确认」；影子重试单独一行 |

完成行示例：`完成：确认删除 1200，未生效 0，待确认 0（影子重试救回 11）。用时 42s。` 中途停止则前缀「已停止。」

## v2.2.13 → v2.2.14 重试不用重做一遍

- 「重试未成功」看的是本地处理记录里仍为未生效或待确认、并且现在就在列表里的评论。重新枚举或导入之后，只要记录还在，按钮就会出现，不必再删一遍才看得见。
- 日志超过约 300 行时，顶部会写明更早的已省略。
- 处理记录超过 2000 条，或浏览器拒绝写入时，会警告一次：更早的「已确认」可能丢失，那些评论不会再被自动跳过。

## v2.2.14 → v2.2.15 处理记录认最新的一次

- 同一条评论多次删除时，跳过、重试、徽标以前可能沿用最早的结果。现在以最新一次为准。
- 打开面板时，状态行写明本地记录有多少条已确认、多少条未成功。
- 「清除记录」会先确认再删掉这份本地记录。列表还在，但这些评论不再被当成已删除。

## v2.2.15 → v2.2.16 换接口和扫描失败不再只进日志

- 本页有重复或缺字段而被跳过的条数会写出来。
- 官方历史翻页失败、单个视频扫描失败都会出现在状态行。扫描过程累计失败视频数，结束时写进日志。

- 重试仍失败才记为失败，方便之后用「重试未成功」。

## v2.2.18 → v2.2.19 登录失效就停，别把没查完的判成已删

- 删除或回查遇到未登录（-101）或 CSRF 失败（-111）时，立刻停止后面的请求。当前这条记为待确认，已经确认删掉的保留。
- 回查时如果评论区没翻完，不再因为「没看见根楼」就判定子评已删除。这种情况改为待确认。
- 登录失效的翻页结果不会被缓存，避免后面的评论沿用一次失败的空结果。

## v2.2.19 → v2.2.20 别在任务中途悄悄关掉

- 间隔小于 200 或大于 5000 会改回范围内，输入框和确认框用的是同一个数，并写回本地设置。打开面板时也会纠正以前存下来的越界值。

## v2.2.20 → v2.2.21 处理记录不再被重复条目撑爆

- 2000 条上限因此按评论数计算。更早的「已确认」不会被同一些评论的重复记录挤掉。
- 打开面板时，如果旧数据里已经有重复，会先合并，并在状态行写明合并了多少条。
